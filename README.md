# 一起放 · PartySync

> 聚会时让所有人的手机同时播放同一首歌。一台电脑当主机，其他人扫码接入，全场在同一个毫秒起播。
>
> 不需要云服务器，不走外网，全部流量在局域网内。

用蓝牙做不到这件事 —— A2DP 是「手机 → 一台音响」的点对点链路，系统层面没有「把手机音频广播给旁边另一台手机」的入口。本项目走的是另一条路：**Wi-Fi 局域网 + 精确时钟同步**。

## 特性

- **不需要云服务器**，不需要联网，不需要账号
- 手机**扫码即用**，不装 App，安卓和 iPhone 都能接入
- 时钟对齐误差 **1–3ms**，起播偏差通常 **20ms 以内**（人耳察觉阈值约 30ms）
- **声学校准**：用电脑麦克风实测每台设备的真实延迟，一次测完全场
- 所有人都能点歌、暂停、切歌，不是主端独裁
- **零运行时依赖** —— `server.js` 只用 Node 内置模块，clone 下来直接 `node server.js`

## 快速开始

需要 Node.js 16+，无需 `npm install`（除非你要重新生成音频）。

**Windows**

双击 `start.bat`，它会自己启动服务并打开浏览器。

**macOS / Linux**

```bash
node server.js --open
```

启动后终端会打印两个地址：

```
主机控制台（本机打开）:  http://localhost:8080/?host=1
手机接入地址:
    http://192.168.1.23:8080
```

## 使用

1. 电脑打开 `http://localhost:8080/?host=1`（**末尾的 `?host=1` 不能省**，否则会显示成手机端界面）
2. 手机连**同一个 Wi-Fi**，扫主机页面上的二维码
3. 手机上点一次「就绪，开始同步」—— 浏览器规定必须先有用户点击才允许自动播放声音，这步绕不过去
4. 主机上点任意一首歌，全场约 3 秒后同时起播

曲库预置了两首：

| 文件 | 用途 |
|---|---|
| **夜航 A小调 100BPM**（77 秒） | 真正的歌，四段编曲。用来感受实际效果 |
| **同步测试 120BPM**（60 秒） | 每拍一声脆响，用来**用耳朵判断有没有错位** |

验证同步用「同步测试」：几台手机同时播，节拍是"一声"就对了，是"啪啦"两下就是错开了。

也可以把自己的 mp3 / m4a / flac / wav 拖进上传区，或者直接丢进 `music/` 目录。

## 工作原理

```
主机 ──HTTP──> 手机A  各自下载完整音频
  └──HTTP──> 手机B
  └──SSE───> 手机A/B  只下发「歌曲ID + 起播绝对时刻」
```

关键设计：**不转发音频流**。每台设备各自下载完整的音频文件，再按主机下发的绝对时间戳对齐起播。这把同步问题从"网络抖动"变成了"时钟精度"，后者好解决得多。

时钟对齐用 NTP 式往返测距：客户端记 `t0` 发出，服务端回自己的时间戳，客户端收到记 `t1`，估算 `偏移 = 服务端时间 − (t0+t1)/2`。取最近 15 次里 RTT 最小的 3 次求平均。

## 播放引擎

用 Web Audio API 的 `AudioBufferSourceNode`，**不是 `<audio>` 元素**。这一点是踩坑踩出来的。

`<audio>` 元素是流式播放，改 `playbackRate` 会重建整条音频管道，在 Android 上直接表现为爆音和断续；网络一抖就欠载卡顿。早期版本用 `<audio>`，结果就是"滋滋声 + 卡滞"。

现在的做法：

1. `fetch` 整首 → `decodeAudioData` 解码成 AudioBuffer 驻留内存
2. `source.start(when, offset)` 在音频线程按采样精度起播，不受主线程卡顿影响
3. 速率微调用 `playbackRate.setTargetAtTime()`，50ms 平滑过渡，DSP 层重采样，无爆音
4. 偏差 < 40ms 不干预；40–350ms 用 ±3% 速率慢慢追；> 350ms 才在新旧节点之间无缝交接（旧的未来某刻停，新的同一刻起）
5. LRU 缓存最近 3 首解码结果

代价是内存：一首 77 秒的歌解码后约 30MB。

## 声学校准

软件层的数字测不到声卡、扬声器、空气传播这些物理延迟。要做真正的对齐，用电脑麦克风实测。

**前提：主机页面必须用 `http://localhost:8080` 打开**。浏览器只对 localhost 和 HTTPS 开放麦克风，局域网 IP 会被拒绝。

点「声学校准」后，电脑和每台手机轮流「啾」一声（2–5kHz 扫频，间隔 1.3 秒），麦克风录下全部声音，用包络互相关定位每一声的实际到达时刻，与计划时刻相减，得到的就是这台设备"耳朵听到的延迟"。结果可一键应用到所有设备。

仿真测试（含 5 阶混响、白噪声、100Hz 电源嗡声）误差在 2ms 以内。

## 自我诊断

协端页面底部有「同步诊断」：

| 数字 | 含义 | 判断 |
|---|---|---|
| 起播误差 | 实际出声比计划晚多少 | 超 100ms = 加载或解码太慢 |
| 当前偏差 | 此刻位置与理论位置之差 | 40ms 内正常 |
| RTT 最小 | 与主机最快往返 | 超 30ms 说明 Wi-Fi 信号差 |
| 偏差曲线 | 最近 45 秒走向 | 上下乱跳 = 网络抖；平稳偏离 = 输出延迟 |

曲线**平稳偏离中线**说明是输出链路的物理延迟，最常见的就是蓝牙耳机（晚 100–300ms），程序测不到，得手动拖「本机延迟补偿」滑块。

## 已知限制

- **受版权保护的流媒体同步不了**。网易云、QQ 音乐这类没有公开播放接口，音频也加密。只能播你自己拥有的文件。
- **多台设备外放会有声学干涉**。两台设备相距 1 米内放同一首歌，相位差会产生梳状滤波、低频抵消，听起来发闷。建议分散摆到房间不同位置、控制在 3–4 台。
- **iPhone 只能当协端**。iOS 会挂起后台，无法持续当服务器；Safari 还要求页面保持前台。
- **主机必须能跑服务**。浏览器不能监听端口，纯网页版做不了。现在是电脑，后续可以打包成安卓 APK 让手机自己开热点。
- 换歌有约 3 秒等待（下载 + 解码），拖进度条 0.9 秒。这是同步精度的代价，不是卡顿。

## 自测

```bash
npm run test:sync      # 同步协议：两台设备收到指令的时间差、startAt 一致性
npm run test:calib     # 校准时隙编排
npm run test:acoustic  # 声学测量算法，7 组仿真场景
```

`test:acoustic` 会合成带混响和噪声的"录音"，塞入已知偏差，验证能否准确反推。

## 文件结构

```
partysync/
├── server.js              零依赖 Node 服务：静态托管 + SSE + 时钟 + 校准编排
├── start.bat              Windows 双击启动
├── public/
│   ├── index.html         主机 / 协端双视图
│   ├── style.css
│   ├── app.js             时钟校准、播放调度、纠偏、诊断面板
│   └── calib.js           声学校准：chirp 合成、麦克风录音、包络互相关
├── music/                 曲库
└── tools/
    ├── gen-music.js       合成完整编曲（鼓/贝斯/和声垫/旋律）
    ├── gen-test-audio.js  合成节拍测试音
    ├── wav2mp3.mjs        WAV → MP3（192kbps）
    └── test-*.js          三组自测
```
